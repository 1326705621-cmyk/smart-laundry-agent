# 面试问答

## 30 秒项目介绍

我独立完成了一个 AI 家庭洗晒助手。它使用 Python、Streamlit 和 SQLite 管理家庭物品及洗晒记录，结合实时天气和物品周期生成计划；大模型通过 Tool Calling 主动查询天气和物品，写操作必须确认。没有模型密钥或外部服务失败时，系统会自动切换到规则模式。目前包含账户、多家庭共享、图片、状态提醒和 70 项自动化测试。

## 1 分钟项目介绍

这个项目解决的是家庭中被褥、衣物、玩偶和宠物用品容易忘记清洗或晾晒的问题。用户可以设置可选周期、上传图片并记录完成时间，系统用确定性规则计算状态；天气模块查询当前城市的降雨、湿度等信息。智能助手没有直接拿到数据库，而是通过天气查询、物品查询和任务完成三个受控工具工作。我限制了最大调用轮数、校验工具参数，并要求写入前由用户确认。数据层用 SQLite 事务保持活动历史与最近日期同步。项目还支持个人账户、多家庭空间和家庭码共享；模型或网络失败时会降级，因此核心流程仍可演示。

## 常见追问

### 为什么使用 Streamlit？

首版目标是快速形成可运行、可演示的 AI 应用闭环。Streamlit 能用 Python 完成表单、状态卡片和交互，减少前后端工程量；业务、数据和 Agent 已拆分到独立模块，后续可替换前端而不重写核心逻辑。

### Tool Calling 和把全部数据拼进 Prompt 有什么区别？

模型只获得工具定义，并根据意图选择查询天气或物品。程序校验参数、执行真实函数，再把结构化结果返回模型。这样事实来源可追踪、上下文更精简，写操作也能被单独控制。

### 如何防止 Agent 误改数据？

工具注册表不提供任意 SQL；写工具只接受稳定物品 ID 和 `wash`/`dry` 动作，参数先校验，未来日期会被拒绝。模型只能生成待确认动作，用户点击确认后程序才执行事务写入。

### 外部服务失败怎么办？

天气请求设置超时和短缓存，失败会返回项目内部错误；模型缺少密钥、超时、限流或解析失败时，直接使用确定性规则生成计划。页面会明确标注运行模式，不把降级结果伪装成 AI 调用成功。

### 家庭共享现在是真正的跨设备实时系统吗？

目前完成的是同一 SQLite 数据库内的多账户、多家庭作用域和共享修改。部署到共享服务器后，不同设备才能访问同一数据库；尚未实现生产级实时推送、分布式并发和 OAuth，因此简历中不会夸大这些能力。

### 项目中最重要的技术取舍是什么？

我把状态判断放在可测试的规则模块，而不是交给 LLM；把 LLM 用于理解请求和组织建议。这样即使模型不可用，业务事实和核心功能仍然可靠。

### 如何测试？

测试使用临时 SQLite、固定日期、模拟天气响应和 Fake LLM Client，覆盖数据库初始化、CRUD、账户隔离、周期边界、天气失败、工具参数、最大轮数、写入确认、事务回滚和规则降级，共 70 项。

## 诚实边界

- 尚未验证生产高并发、真实用户量或商业指标。
- 本地家庭共享不是公网跨设备服务。
- 周期是用户自定义的生活管理建议，不是医学或卫生结论。
- 系统通知和拍照生成动漫图片仍属于后续方向。
